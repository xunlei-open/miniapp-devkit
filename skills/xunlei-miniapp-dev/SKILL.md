# 迅雷微应用开发

**迅雷微应用是运行在迅雷客户端中的轻量 Web 应用**：用 HTML、CSS、JavaScript（或 Vue / React）编写界面，以包内 `index.html` 为入口，连同 `manifest.json` 和静态资源构建打包，由迅雷的 WebView 容器加载。已有的前端开发经验可以直接复用；页面还可通过宿主注入的 `xunlei` 调用下载任务、存储等能力。资源随包提供，联网请求需声明权限与地址白名单。

默认目标是一个用户能在迅雷中打开、交互并完成核心功能的 UI 微应用，交付可加载的 `dist/` 目录，按需生成 ZIP 安装包。

以 miniapp-devkit 的类型定义和实现作为 API 标准，围绕用户需求完成可构建、可在迅雷中验证的微应用。沿用已有工程的框架、语言和包管理器，不因使用本技能而重新创建工程。

## 开始开发

1. 读取目标项目约定、`package.json`、`manifest.json`、`miniapp.config.*` 和微应用类型包版本。在 devkit 仓库中，以 `packages/miniapp-types/src/index.ts`、CLI 实现及示例为准；独立工程以安装版本的类型与对应 devkit 实现为准。
2. 默认从 UI 页面开始：明确用户在页面上的输入、操作和结果反馈，使用包内 `index.html` 入口。无需先让用户选择应用形态。
3. 新工程使用官方脚手架。无指定技术栈时，简单表单可用 Vanilla + TypeScript，复杂交互根据需求选择 Vue / React；已有工程保持原选择。
4. 页面采用移动端优先的响应式样式，桌面端默认以 `manifest.window` 的 900 × 700 为设计与验收基准，主要内容和操作尽量一屏呈现、不出现整页滚动条；窄屏按需重排。非必要不改变默认窗口尺寸；业务内容确有需要时可以调整，并按最终尺寸验证布局。编写或调整 UI 前读 [响应式布局](references/responsive-ui.md)。随后按功能接入平台 API，跑通“输入 → 操作 → 结果反馈”的核心流程，同步更新清单中的权限、网络白名单和入口。
5. 只有功能需要介入迅雷下载生命周期时，再引导到下方的事件扩展；普通页面下载无需预先创建事件目录或声明 scripts。

## 按需进阶：下载事件

页面中输入链接、请求接口解析出下载地址，再调用 `xunlei.tasks.create`，通常即可完成下载功能，不必使用事件。

当用户需要“在迅雷提交某类链接时自动解析”“任务开始前改写地址”或“下载失败 / 完成后执行逻辑”，再说明事件能介入下载生命周期，并读取 [事件脚本](references/events.md)。先在现有 UI 工程中添加所需的单个事件入口与精确匹配规则，保留页面作为主要入口；不要预先加入四种事件模板。用户明确要求无界面的自动处理时，再按事件参考中的说明省略页面。

## 开发边界

- `xunlei` 是宿主注入的全局对象，类型包不是浏览器运行时 SDK，无需运行时 import。
- 页面依赖和静态资源随包构建。容器限制远程资源加载、iframe、外部跳转和 `window.open`；`network` 权限不会解除页面资源限制。
- 下载使用 `xunlei.tasks.create`；导出内存数据使用 `xunlei.runtime.blob.createObjectURL` 再创建任务，不用 `<a download>` 或浏览器原生下载。
- 清单变更后重启开发服务并在迅雷重载。加载输出目录（默认 `dist`），不是源码目录。
- 构建与打包不自动做类型检查。完成工程支持的类型检查和相关验证，再构建、按需打包；浏览器预览和编译通过不能代替宿主验证。

## 交付

说明完成的功能、产物路径、运行与加载方式、已执行检查。环境没有支持微应用的 Windows 迅雷客户端时，明确列出待做的宿主验证，不声称已联调成功。生成安装包不代表已上架。

最后引导用户通过以下两种方式体验，并使用实际输出路径：

1. **本地加载（推荐开发调试）**：启动并保持 dev server 运行，在迅雷微应用管理页面选择「加载本地应用」，加载 `dist` 目录，页面修改支持 HMR。
2. **安装 ZIP**：将 `release` 目录中生成的 ZIP 直接拖拽到迅雷微应用管理页面进行安装，无需保持 dev server 运行。

尚未生成 ZIP 时，提供项目实际的打包命令，不把预期路径描述为已有产物。具体命令与说明见 [工程与交付](references/project.md#安装体验指引)。
