# 类型维护规范

- 迅雷客户端 25.1.30 为首版基线，基线能力不逐项标注版本。基线之后新增公开类型、接口方法、字段或可选值，以及扩展现有能力时，必须在对应声明的 JSDoc 中注明最低迅雷客户端版本，统一使用 `@since 迅雷客户端 >= <版本号>`，例如 `@since 迅雷客户端 >= 25.1.60`；不使用裸版本号，以免与 npm 包版本混淆。
- 全新类型的初始成员可沿用类型声明上的版本要求；向既有类型新增成员时，在新增成员处单独标注。既有能力新增参数、取值或行为时，注明该增量及其最低版本，保留原有能力的版本要求。
- 最低版本以需求或宿主实现确认的信息为准；版本不明确时先确认，不推测或沿用其它能力的版本。仅修正文案或类型表达、未增加宿主能力时，无需提高最低版本。
- 核对历史版本时，同时检查迅雷发布标签中的宿主实现、固定的 runtime 版本及其注入链路；版本分支可能追加合并，不单凭分支名或类型声明判断。遇到灰度包差异或后续版本回退时，`>=` 标注采用可连续支持该能力的版本基线。
- README 面向外部开发者，围绕安装、使用方法和能力约束编写；版本要求保留在类型声明中，不在 README 添加维护用版本汇总、内部讨论、源码核对过程或分支发布细节。
- 修改 `src/index.ts` 后，在仓库根目录运行 `pnpm skill:sync` 同步类型参考。
- 完成前对照类型 diff，确认每项新增能力均有版本说明、已有标注仍准确，并检查同步后的参考与源类型一致。
