# 响应式布局

默认采用移动端优先的响应式布局，尽量让同一套页面覆盖手机宽度、窄窗口和桌面宽屏。桌面端通常以默认窗口 900 × 700 为设计与验收基准，主要内容与操作尽量一屏呈现，避免整页横向或纵向滚动条。非必要不改变默认尺寸；业务内容确有需要时可以调整，用户有明确尺寸约束或已有工程有约定时遵循其要求。这里约定的是页面适配方式；宿主 API 的平台支持仍以目标客户端为准。

## 默认桌面布局（900 × 700）

- 新应用默认使用 `manifest.window: { width: 900, height: 700 }`，优先让 UI 适配窗口；优化布局后仍无法合理容纳核心内容时，可按实际需要调整清单尺寸。宿主窗口尺寸与页面内容视口可能不同，实际可用空间以宿主内测量结果为准，不假定页面内容高度等于清单中的窗口高度。
- 分配标题、工具栏、主内容和底部操作区的高度，减少大标题、重复说明与过量留白。宽度允许时，把预览区与参数区并排，避免把移动端的纵向堆叠原样放进桌面窗口。
- 图片裁剪等工具让预览区随剩余空间缩放，图片或 Canvas 不以原始尺寸撑开页面；主操作保持可见。Flex / Grid 的可收缩区域按需设置 `min-height: 0`、`min-width: 0`，网格轨道可用 `minmax(0, 1fr)`。
- 默认状态和核心操作流程以无整页滚动条为目标。长任务列表、展开详情等动态内容确实放不下时，仅让相应内容区滚动，保持主要操作可达；窄屏或文字放大时允许必要的纵向滚动。
- 不用全局 `overflow: hidden`、缩小文字或整页缩放制造“一屏适配”。先调整结构、留白与预览尺寸，确保内容完整、可读、可操作。

## 布局原则

- 基础样式服务窄屏，优先单列和清晰的操作顺序；空间充足时通过 `min-width` 媒体查询增强为多列、侧栏或横向工具栏。断点由内容何时拥挤决定，不根据设备型号或 User-Agent 切换布局。
- 使用 Flex / Grid、流式宽度和适当的 `max-width`；间距与字号优先使用 `rem` 等相对单位。避免固定页面宽度、整页缩放或用绝对定位搭建主体布局。`manifest.window` 决定默认桌面验证尺寸，布局仍应随实际内容视口伸缩。
- Flex / Grid 子项需要收缩时设置 `min-width: 0`；长链接、文件名允许换行或提供可查看全文的省略方案。图片和视频限制在容器宽度内并保持比例。
- 表单、按钮组和导航在窄屏自然换行或堆叠。宽表格可改为保留关键字段的卡片，确需二维展示时只让表格区域横向滚动；不要用全局 `overflow-x: hidden` 掩盖内容溢出。
- 尽量保持一套 DOM 和业务状态，通过 CSS 调整布局；不要分别维护移动版与桌面版页面。

## 视口与交互

页面保留视口声明，并允许用户缩放：

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

- 核心操作可通过触控和键盘完成，不依赖 hover；保留清晰的焦点样式。触控按钮与图标按钮建议至少提供约 44 × 44 CSS px 的点击区域，并留出间距；这属于设计建议，不是宿主硬性尺寸限制。
- 不通过隐藏功能来适配窄屏。弹窗应限制宽高、允许内部滚动，关闭与确认操作始终可达。
- 固定或吸底操作栏为正文预留空间，避免遮挡内容。需要贴近屏幕边缘时考虑 `env(safe-area-inset-*)`；有输入框时检查软键盘出现后仍能滚动到输入和提交区域。
- 窄屏优先让内容自然撑开；桌面工作区可使用视口高度分配可收缩的主内容区。使用 `dvh` 等单位时保留兼容回退，并为超长内容提供可达的局部滚动区域，避免固定高度裁切内容。

## 布局验证

新增页面或影响布局的改动，按实际可用的预览工具检查：

- 首先按最终配置的窗口尺寸检查桌面预览（默认 900 × 700），以及宿主实际内容视口：默认状态和核心操作的主要内容应一屏可见，无非预期的整页横向或纵向滚动；不要仅在最大化窗口下验收。
- 再检查代表性的窄屏、常见手机宽度和桌面宽度，例如 320、390、768、1280 CSS px，并连续调整宽度观察断点附近；这些是验证样本，不是强制断点。
- 没有非预期的整页横向滚动、文字截断、按钮重叠或弹窗超出视口；宽屏空间得到合理利用。
- 长文件名、长链接、空列表、加载和错误状态仍可用，文字放大后关键操作可达。
- 可用时验证触控、键盘焦点与输入场景。浏览器可验证布局，平台调用仍在目标迅雷客户端验证。

无法运行预览时完成静态检查，并在交付中说明尚未实际验证的尺寸或交互，不把 CSS 检查当作视觉验证通过。
